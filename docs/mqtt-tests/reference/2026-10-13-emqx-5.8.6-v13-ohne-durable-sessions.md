## Broker limitations found

- **MTLS-07 FAIL**: The broker accepts a client certificate without the clientAuth extended key usage. The certificate profile is an OPEN decision (ENTC-31); enforce it in the broker or in the PKI.
- **MTLS-08 FAIL**: No revocation check is active (CRL, OCSP or registry lookup), so a revoked certificate can still connect. Revocation strategy is OPEN (ENTC-58/ENTC-31). Check the broker's CRL/OCSP support (e.g. Mosquitto crlfile, EMQX enable_crl_check) and test with certs/negative/crl.pem.
- **ID-01 FAIL**: The broker accepts a Client ID that is not the one authorized for the certificate and lets it displace the legitimate session. Mismatched identity bindings must be rejected (ENTC-47/58: credential -> serial -> authorized Client ID); classify NATIVE / CONFIGURATION / PLUGIN / CUSTOM for ENTC-59.
- **ID-03 FAIL**: The broker accepts a Client ID other than the derived one authorized for the certificate (here: the plain certificate CN). The binding credential -> authorized Client ID needs a registry lookup in the broker (plugin, auth hook or external service).
- **DUP-01 FAIL**: The broker applies the MQTT session takeover. The acceptance requirement is to avoid a silent takeover of the active session (Current State 08.10, section 5); needs broker support or an extension.
- **LEG-01 FAIL**: The broker cannot derive the Gateway ID from a certificate without CN/SAN, so the legacy gateway is rejected or has no permissions. Legacy AWS IoT certificates need a registry lookup (certificate fingerprint -> Gateway ID) or re-issuance with the Gateway ID in CN/SAN (ENTC-31).
- **RST-01 FAIL**: The persistent session or its queued QoS 1 command did not survive the broker restart. Check the durable session storage of the broker (e.g. EMQX durable sessions, Mosquitto persistence) and repeat with the intended HA setup (failover is OPEN, ENTC-58).
- **REV-01 FAIL**: Revoking a certificate does not reach the connection that is already open (or not even new connections). Active session termination is OPEN (ENTC-31); needs a revocation feed plus an admin/kick API or an extension.
